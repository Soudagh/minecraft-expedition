# Expedition: запись боевых испытаний (QA)

Для изолированной копии сборки 0.26.0-equipment-balance-dev с текущими locked JAR. Два скрипта записывают серверные события; они не меняют игровые коэффициенты и не создают тестовых игроков/боссов. Настоящие клиентские прогоны ещё предстоит выполнить.

1. Скопировать папку kubejs из архива в корень **тестовой копии** сервера. Перезапустить сервер: startup script требует перезапуска. При старте проверить отсутствие ошибок скриптов.
2. Выбрать конкретного игрока и цель. `/tag <имя игрока> add exp_combat_observe`; `/tag <UUID цели> add exp_combat_target`. UUID цели определять на своём сервере; не помечать всех мобов сразу.
3. Создать `kubejs/export/combat-capture-control.json`: `{"enabled":true,"session":"longsword-baseline-01"}`. Имя сессии — до64 маленьких латинских букв, цифр, `_` и `-`.
4. Выполнить серию, записать видео и здоровье цели до/после. Обычные комбо и специальные навыки — отдельные серии. Указать броню, еду, навыки, дистанцию, материал/форму оружия и фактические силы.
5. Остановить запись: `{"enabled":false,"session":"longsword-baseline-01"}`. Через секунду получить `kubejs/export/combat-capture-longsword-baseline-01.json`. Снять оба тега командами `/tag ... remove ...`.
6. Запустить Python3: `python tools/summarize_combat_capture.py kubejs/export/combat-capture-longsword-baseline-01.json --output longsword-baseline-01-summary.json`.

Сохранение раз в секунду, лимит20000строк. Анализатор принимает только остановленную запись с dropped=0 и пустым errors. Сессии с ошибками/переполнением необходимо повторить. При ошибке боевого обработчика регистратор отключает запись; не пробрасывает исключение в код атаки.

## Серии

- Этап III: пять Netherite форм без рун — Rapier/Sai/Longsword/Katana/Greathammer. По три серии30сек без Sharpness и брони; затем тот же комплект с полным незеритом, отдельно SharpnessV.
- Runic со Slow на этапеIII: отдельные серии на тех же формах. Зафиксировать различия характеристик между Netherite/Runic. Пустая руна на Runic может снова случайно назначиться, поэтому удаление NBT не даёт стабильной серии «без рун».
- ЭтапVII: Brimstone Claymore с SharpnessV, пробуждение4/8. Сравнить пустые гнёзда, Slow, Onslaught с одинаковым внешним замедлением, Slow+Onslaught. Подтверждено нативно, что сочетание доступно на одном оружии; в ранних этапах уникальное оружие закрыто. Не повышать общий этап живого игрового мира ради теста.
- Отдельно проверить внешнее Haste и допустимые offhand атаки. Пассивное оружие во второй руке не заменяет реальное попадание этой рукой. Brimstone является двуручным.
- Затем по три подготовленных попытки босса вчетвером: длительность, смерти, расходники, безопасный урон/контроль.

## Что означает запись

LivingDamage на NORMAL priority фиксирует промежуточный amount, который другие обработчики могут изменить. Сумма amount не является гарантированной потерей HP или DPS. Анализатор показывает интервалы между наблюдаемыми положительными событиями урона: несколько попаданий одного приёма могут попасть в один тик. Это не частота нажатий и не число попыток атаки.

Player samples включают оружие, характеристики, здоровье, эффекты, вес, выносливость и режим Epic Fight. Доли эффектов — доли записанных образцов, не гарантированный uptime всей сессии. Клиентские нажатия, промахи, число звеньев комбо и окончательное HP цели прибор не измеряет. Для вывода о DPS нужны видео, независимое измерение HP/лечения цели и длительности боя. Server ticks не равны точному времени по часам при лагах.

Чтобы удалить прибор, остановить запись, удалить два zz_combat_capture.js и перезапустить тестовый сервер. Сохранённые export JSON остаются.
