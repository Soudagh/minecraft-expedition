# Slow → Onslaught на нативных боссах: аудит 0.32

Игровая версия 0.26, коэффициенты и ограничения экипировки сохранены. Проверены locked JAR Graveyard, EEEAB и Simply Swords; код и runtime-результаты сохранены отдельно. Сущности создаются без добавления в мир. Проба вызывает нативное добавление эффектов и `GemPowerComponent.postHit`, принудительно задаёт шанс Slow=100 и восстанавливает его в finally. Это проверка обработчиков на свежих сущностях, не успешные попадания Epic Fight, не бой/фаза босса и не DPS.

## Иммунитет и запуск рун

| Цель | Slowness принят | Slow / Greater Slow запускают Onslaught |
|---|---|---|
| Контрольная корова | Да | Да |
| Контрольный слизень | Да | Да |
| Corrupted Champion (`graveyard:lich`) | Нет | Нет |
| Relic Annihilator | Нет | Нет |
| Realmwarden | Нет | Нет |

Проверены оба вида Slow, пробуждение Brimstone 4 и 8: 20 сочетаний. На контрольных целях Slow III длится 25/50 тиков, Onslaught — 40/80. Вызов callback не меняет здоровье цели. Обычные корова/слизень лишь проверяют типы носителей SLB: они не воспроизводят установленные хитбоксу эффекты, сцену и командную модель босса.

`LichEntity` безусловно возвращает false из варианта добавления эффекта с источником (`m_147207_`). `EntityAbsRelicron` прямо отклоняет Slowness и Poison, затем передаёт остальные эффекты базовому классу. `EEEABMobLibrary` наследует политику `EEEABMobEntity`: для IBoss требуется полезный эффект и разрешение ванильного класса. В QA оба EEEAB-босса принимают Regeneration, Champion её отклоняет. Нельзя обобщать это до запрета любого эффекта у всех модовых боссов.

## Ранее полученный Onslaught и Weakness

Дополнительная QA: 5 целей с заранее назначенным Onslaught (остаток 31 тик) и 5 с Weakness. Callback на иммунных боссах сохраняет прежние 31 тик Onslaught без обновления; на корове/слизне обновляет до 80. При Weakness Onslaught не появляется на любой из пяти целей, хотя Slow на контрольных целях применяется. Предварительный бафф назначен пробой, не заработан реальным ударом по прислужнику; полный ход времени и переход между целями в клиенте здесь не воспроизводятся.

Финальный полный запуск: **103 проверки**, 20 сочетаний рун, 5 сценариев сохранения баффа и 5 сценариев Weakness. Базовые 20 результатов совпали с предыдущим успешным запуском на 93 проверки.

## Доступность при первом прохождении

Runic требует общий этап III, уникальное оружие — VII. Этап победы присваивается после босса, поэтому первый бой с ним проходит на предыдущем этапе.

| Босс основного маршрута | Этап перед первым боем | Runic / двухсокетный unique разрешены |
|---|---:|---|
| Abyss Watchers | 0 | Нет / нет |
| Corrupted Champion | I | Нет / нет |
| Lothric | II | Нет / нет |
| Sunflower | III | Да / нет |
| Relic Annihilator | IV | Да / нет |
| Soul of Cinder | V | Да / нет |
| Nightlord | VI | Да / нет |
| Melkor | VII | Да / да |
| Realmwarden | VIII | Да / да |

Следовательно, цена пары Slow+Onslaught не является обязательной стоимостью прохождения первых семи боссов. Для доступного двухсокетного оружия ключевые первые бои — Melkor и Realmwarden. На Realmwarden собственный Slow не запускает Onslaught; возможность принести бафф с другой цели нужно учитывать отдельно. Повторные бои и обычные мобы имеют иной контекст доступности.

## Следующий боевой тест

Для Realmwarden провести серии без прислужников и с доступным источником предварительного Onslaught: записать смену цели, остаток баффа, обновления, Weakness, реальные попадания и выносливость. Для Melkor отдельно подтвердить приём Slowness реальным хитбоксом и запуск цепочки, затем проверить поведение модели и фаз. Иммунитет не даёт основания автоматически ослаблять либо усиливать руны: результат зависит от доступных дополнительных целей и длительности окон атаки.
