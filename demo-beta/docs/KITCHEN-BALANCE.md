# Снабжение кухни и проверка энергетики

Следующая локальная итерация после 0.23. Книга и состав модов сохранены. Изменены две партии напитков Brewin’ and Chewin’; обычная еда и остальные напитки сохраняют прежние рецепты.

| Напиток | Общий этап употребления | Настой на одну партию 1000 mB |
|---|---|---|
| Saccharine Rum: Sweet Heart, лечение за счёт насыщения | II, Champion | Один арбуз + один `material_champion` |
| Red Rum: Raging, боевое усиление | III, Lothric | Один светогриб + один `material_lothric` |

Материалы кампании воспроизводятся после общей победы по уже действующим производственным партиям. Повторное убийство босса для каждой партии напитка не требуется. Эти материалы связывают повара с подготовкой Create/Botania; отдельный завод GT ради двух ранних напитков не нужен.

## Что изменено в бочке

Настой делается обычным shapeless-рецептом из двух предметов. В партии Saccharine Rum настой заменяет арбуз; в партии Red Rum — светогриб. Оригинальный ингредиент расходуется при изготовлении настоя: он не исчезает из общей стоимости. Остальные ингредиенты, базовая жидкость, объём, температура, время и опыт сохранены. Число слотов бочки осталось три/четыре; пятый ингредиент не добавлен.

Одна партия 1000 mB даёт четыре обычные кружки по 250 mB, поэтому дополнительный материал кампании расходуется на четыре напитка. Переливание Create, кружки и жидкостные ID сохранены; обычная производственная автоматизация остаётся доступной.

## Найденные и переданные кружки

Настоящее серверное событие начала использования предмета Forge проверяет общий этап для обоих напитков. До открытия питьё не начинается, кружка не расходуется. Проверка не зависит от способа получения предмета. На открытом этапе напиток используется штатно.

Нативные положительные и отрицательные эффекты не переписаны. В частности, Sweet Heart расходует насыщение, а Raging имеет собственную механику накопления. Кухня не получает искусственного ограничения на каждую обычную еду. Правило «одна еда + один напиток», сочетания нескольких положительных эффектов, настоящие бои с Epic Fight и темп готовки вчетвером ещё не проверены полностью.

## Энергетика: что проверяется

Установленная версия CreateAddition по умолчанию использует 75% эффективности генератора. QA сравнивает нативную функцию производства генератора с точной формулой потребления мотора из закреплённого JAR и фактически загруженными значениями конфига для всех целых скоростей 1–256 RPM. Такая проверка не является сборкой линии с произвольным набором передач и нагрузок.

HBM `converter_block` имеет HE/FE-обмен 1:1. QA проверяет приём, выдачу, чистоту simulate и полный возврат партии 1000 единиц через настоящую энергообёртку. Коэффициенты не меняются.

GT имеет штатный EU→FE с отношением 1 EU = 4 FE; обратные FE→EU-конвертеры отключены. QA проверяет фактически загруженную конфигурацию. В этом направлении HBM/Create не питают GT обратно через такой конвертер. Все способы получения топлива, преобразование жидкостей, генераторы других модов и собранные многоблоки этим аудитом не покрыты.

## Обновление

Полностью перезапустите клиент и сервер: добавлены два предмета KubeJS. Старые кружки, жидкости, чанки и квесты сохраняются. В уже настроенных шаблонах производства двух напитков замените арбуз/светогриб соответствующим настоем и добавьте крафт настоя.

Прямой вызов функции мотора через Rhino недоступен из-за необязательного типа ComputerCraft; reflection ограничен фильтром классов KubeJS. Формула подтверждена байткодом, сам мотор не запускается. [Источники энергетического аудита](ENERGY-BALANCE-SOURCES-0.24.json).
