# Следующий этап баланса: реальные комбо, руны и роли

Игровая база: 0.26.0-equipment-balance-dev; исходный аудит зачарований и анимаций — [0.27](ENCHANT-RUNE-CADENCE-BALANCE.md). Численные изменения вводим после измерений. Эта инструкция не означает, что клиентские прогоны уже выполнены.

## 1. Контрольный бой Epic Fight

Нужен настоящий клиент в боевом режиме. Пять форм: Rapier, Sai, Longsword, Katana, Greathammer. Доступная серия без рун использует Netherite, серия с выбранной руной — Runic; характеристики обоих материалов записывать отдельно. Чистый эффект руны можно оценить только на том же оружии со стабильным контролируемым состоянием. Одинаковые расстояние, положение и тип цели; сначала одиночная неподвижная цель без брони, затем одинаковая защищённая цель. Ступень III, без случайных дополнительных баффов. Обычное комбо и специальный навык измерять отдельно; навыки и способы ввода записать.

Сначала Netherite без рун и Sharpness, без брони: три серии по 30 секунд на форму после прогрева. Затем полный незерит на тех же условиях. На повторяемой серии добавить Sharpness V. Protection IV испытывать отдельно на получаемом уроне, а не менять одновременно с оружием. Одинаковая дистанция не доказывает одинаковую доступность попаданий; промахи отмечать по видео.

Фиксировать: число успешных попаданий, интервалы внутри и между комбо, здоровье цели до/после, расход и восстановление выносливости, промахи, длительность специального навыка. Несколько попаданий одного приёма сохранять отдельными событиями. Интервал между попаданиями не называть частотой нажатий. DPS считать по фактической потере здоровья цели за измеренное окно с учётом её лечения и новой цели; суммы промежуточных событий недостаточно.

## 2. Руны и время действия

На этапе III сравнить доступные Netherite без руны и Runic со Slow, фиксируя различия характеристик материалов. Не считать разницу чистым эффектом Slow. Обычный Runic при пустой силе делает новый случайный выбор; удаление NBT само по себе не создаёт стабильную серию без руны. Onslaught и сочетание Slow + Onslaught на одном Brimstone Claymore испытывать отдельно на этапе VII, пробуждение 4/8. [Нативный допуск и кузница проверены в аудите 0.29](RUNE-SOCKET-BALANCE.md). Отдельно проверить реально разрешённую комбинацию двух рук. Зафиксировать NBT и фактические силы, обе руки, пробуждение и доступность сочетания в выживании. Прямой вызов callback не доказывает, что комбинация доступна игроку.

Для Onslaught делать серии с паузами и непрерывным обновлением; отмечать Haste, Weakness и повторное срабатывание. Отдельно сравнить внешнее Haste, без него и после окончания Onslaught. Для Slow проверить контроль босса и повторные обновления; модификация длительности обычного моба не доказывает действие на босса. Stormlash проверить на одной и нескольких целях; урон вторичных целей учитывать отдельно.

## 3. Комплекты ролей и боссы вчетвером

После измерений собрать доступные по ступени комплекты: ближний бой, защита/контроль, дальний бой/магия, поддержка. Для каждого указать оружие, броню, руны, навыки, еду, лечение, стоимость подготовки и производство расходников. Проверить сильнейшее найденное сочетание отдельно, включая одного сильного игрока.

Для каждого выбранного босса — три попытки подготовленной четвёркой после знакомства с атаками. Целевые ориентиры из FULL-BALANCE: 3–8 минут для раннего босса, 6–12 для позднего. Сначала устранить безопасное убийство и бесконечный контроль, затем корректировать HP/урон. Записывать смерти, расходники, активное время боя, время подготовки и найденные обходы.

## Запись серверных событий (только QA)

Скопировать `tools/combat_capture_startup.js` в `kubejs/startup_scripts/zz_combat_capture.js`, `tools/combat_capture_server.js` в `kubejs/server_scripts/zz_combat_capture.js` изолированной копии. Нужен перезапуск сервера. `onslaught_cycle_probe.js` — отдельная автоматическая FakePlayer-проба, для клиентского боя её не устанавливать.

Пометить участвующего игрока командой `/tag <имя> add exp_combat_observe`, конкретную цель — `/tag <UUID> add exp_combat_target`. Локально создать `kubejs/export/combat-capture-control.json`:

```json
{"enabled":true,"session":"longsword-baseline-01"}
```

После серии заменить enabled на false. Не менять session при enabled=true в ходе одной серии. Получить `kubejs/export/combat-capture-<session>.json`; снять теги после испытания. Session допускает только маленькие латинские буквы, цифры, `_` и `-`, до 64 символов. Сохранение каждую секунду; не более 20000 строк, переполнение видно в dropped. Для количественной оценки принимать только dropped=0 и пустой errors. При ошибке обработчика запись отключается, ошибка сохраняется; обработчик не выбрасывает её в боевой код.

Запись содержит server game tick, UUID игрока/цели, AttackEntity/LivingAttack/LivingDamage и ежетиковые образцы здоровья игрока, характеристик, эффектов, веса и выносливости Epic Fight. Forge listeners имеют NORMAL priority: observedAmount может измениться позже; это не гарантированный окончательный урон. Клиентские нажатия, промахи и здоровье цели после всех обработчиков не записываются. Видео и отдельное измерение здоровья цели обязательны для полноценного вывода о DPS. Нативная проверка одной атаки служит проверкой инструмента, не заменяет клиентский бой.

## Порядок решения

1. Проверить прибор и полный цикл эффектов.
2. Снять реальные комбо и интервалы попаданий на клиенте.
3. Проверить руны и зачарования в этих же условиях.
4. Сопоставить комплекты ролей на боссах вчетвером.
5. Внести минимальные коэффициенты/ограничения по результатам и повторить только затронутые серии.
6. Вернуться к партиям расходников, времени производства и энергетическим циклам, чтобы стоимость усиленного комплекта соответствовала его пользе.

Точные поздние комплекты и результаты перековки: [RUNE-SOCKET-BALANCE](RUNE-SOCKET-BALANCE.md). Прямой callback Onslaught на обычном Runic из 0.28 не считается доступным комплектом выживания.
